# Exemplos e runtime de Cloudflare Agents para o review do Holon

## Escopo e método

Verificado em 2026-10-03 contra a [documentação oficial de Agents](https://developers.cloudflare.com/agents/) e seu [índice](https://developers.cloudflare.com/agents/llms.txt). Foram examinados os cinco exemplos publicados e as páginas explicativas relevantes a execução, Think, sessão, Workflows, ferramentas, modelos e observabilidade. O índice inclui ainda comunicação interativa, pagamentos, Code Mode, Pi e recursos de servidores MCP; esses temas foram triados, mas seus guias operacionais não foram auditados em profundidade porque o Holon não implementará esses canais ou capacidades nesta migração. As conclusões abaixo são inferências para o Holon; os tutoriais da Cloudflare não são testes de integração do projeto.

O estado real do Holon nesta data é `ReviewWorkflow extends WorkflowEntrypoint`, iniciado pelo control plane, ledger próprio, executor com Sandbox e um gerador AI SDK próprio. A [ADR-0018](../decisions/0018-adopt-two-phase-decoupled-review-generator.md) continua aceita. O [plano de migração](../planning/think-review-agent-migration.md) é proposta e não altera a arquitetura vigente.

## O que os cinco exemplos ensinam

| Exemplo                                                                           | Padrão demonstrado                                                                                                            | Aplicação ao Holon                                                                                                                                                         |
| --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Chat agent](https://developers.cloudflare.com/agents/examples/chat-agent/)       | `AIChatAgent`, AI SDK, stream, tools de servidor/cliente e aprovação; roteamento de chat por HTTP/WebSocket.                  | Mostra separação entre entrada, sessão e tools. Não copiar o loop `streamText`, cliente de chat ou aprovação interativa para review automático; Think deve possuir o loop. |
| [Slack agent](https://developers.cloudflare.com/agents/examples/slack-agent/)     | Um agente por workspace, eventos e identidade do canal, contexto de thread.                                                   | Confirma que a chave de instância é limite de isolamento. Para o Holon, chave por run/shard, com webhook GitHub validado antes da chamada; não por workspace ou conversa.  |
| [Voice agent](https://developers.cloudflare.com/agents/examples/voice-agent/)     | `Agent` com canal WebSocket e pipeline de áudio em tempo real.                                                                | Separar adaptadores de canal da lógica do agente. Voz, WebSocket e UI não pertencem ao review.                                                                             |
| [Browser agent](https://developers.cloudflare.com/agents/examples/browser-agent/) | Browser Run com `browser_search` e `browser_execute`; o modelo escreve JavaScript para CDP em uma sessão nova a cada chamada. | Capacidade incompatível com o contrato mínimo de tools de leitura do repositório. Não adicionar Browser Run, Worker Loader ou execução dinâmica de código ao reviewer.     |
| [Email agent](https://developers.cloudflare.com/agents/examples/email-agent/)     | `Agent` recebe e envia email; respostas podem ser roteadas com cabeçalhos assinados.                                          | Reforça validação de identidade e proveniência na borda. Não criar canal de email nem confiar em cabeçalhos ou texto fornecidos pelo modelo como autorização.              |

Os exemplos são tutoriais de canais e capacidades, não uma arquitetura de PR review com Think. Muitos usam `Agent`/`AIChatAgent` e loop AI SDK próprio. A semelhança de nome com o produto não justifica copiar seus endpoints, tools ou privilégios.

O [guia de testes](https://developers.cloudflare.com/agents/getting-started/testing-your-agent/) usa o plugin oficial Vitest para Workers: o corte vertical deve exercitar a instância DO e sua persistência, não apenas funções puras. [Padrões agentivos](https://developers.cloudflare.com/agents/concepts/agentic-patterns/) descrevem paralelização e orquestrador/trabalhador como padrões, sem fixar o algoritmo de shard do Holon. [Human in the loop](https://developers.cloudflare.com/agents/concepts/agentic-patterns/human-in-the-loop/) cobre espera por aprovação, elicitação MCP e Code Mode; o review automático e somente leitura não precisa de aprovação dentro do agente. O publisher do host continua responsável pelos efeitos no GitHub.

## Achados transversais das páginas explicativas

1. **Workflow e Agent têm papéis distintos.** [Conceitos de Workflows](https://developers.cloudflare.com/agents/concepts/workflows/), [integração de Workflows](https://developers.cloudflare.com/agents/runtime/execution/run-workflows/) e [submissões do Think](https://developers.cloudflare.com/agents/harnesses/think/programmatic-submissions/) posicionam Workflow como dono de passos duráveis, retries e esperas; o Agent possui estado e turno. Isso sustenta manter o Workflow e o ledger do Holon como autoridade causal. `submitMessages()` oferece aceitação durável, chave de idempotência, inspeção e cancelamento da submissão, mas a resposta chega depois; não é retorno estruturado síncrono nem substituto automático do checkpoint do Workflow.
2. **Há duas integrações possíveis para a saída do Think, com semânticas diferentes.** [`ThinkWorkflow.step.prompt()`](https://developers.cloudflare.com/agents/harnesses/think/workflows/) inicia um turno e devolve objeto Zod durável. Ele exige `ThinkWorkflow` iniciado por `agent.runWorkflow()`; iniciar diretamente pelo binding não injeta o contexto do agente. O objeto é emitido por `think_final_answer`, uma tool interna forçada durante streaming. O modelo precisa respeitar tool call forçada em streaming, `maxSteps` deve comportar investigação e resposta, e `beforeTurn` não pode sobrescrever `toolChoice`. Já [`Output.object` em `beforeTurn`](https://developers.cloudflare.com/agents/harnesses/think/lifecycle-hooks/) configura saída estruturada por turno, podendo ser usado no segundo turno sem tools. Nenhum dos dois encaixes está provado com o Workflow do Holon, sua rota AI Gateway e o modelo pretendido. Em especial, uma allowlist que exclua a tool interna pode inviabilizar `step.prompt()`.
3. **RPC de chat não equivale a conclusão durável.** A [API programática de Think](https://developers.cloudflare.com/agents/harnesses/think/sub-agents/) avisa que `chat()` pode chamar `onInterrupted` e resolver a promessa sem resposta terminal quando a continuação foi agendada. Um Workflow que trate a resolução da RPC como sucesso pode publicar saída parcial. `submitMessages()` tem estados `pending/running/completed/aborted/skipped/error` e cancelamento durável; a integração precisa mapear esses estados ao ledger e recuperar o resultado validado, sem inferir sucesso de stream parcial.
4. **Sessão persistente não é memória confiável entre revisões.** A [Session API](https://developers.cloudflare.com/agents/runtime/lifecycle/sessions/) é experimental, armazena conversa em SQLite por padrão, suporta context blocks, busca e compaction. `withCachedPrompt()` congela o prompt depois do primeiro uso, inclusive após hibernação. Para Holon, run/shard e digest de política devem estar fixos na identidade/configuração da sessão; não habilitar memória editável nem busca entre runs. A [página de memória](https://developers.cloudflare.com/agents/concepts/conversation-state-and-memory/) descreve capacidades, não valida reuso de evidência após novo SHA.
5. **A superfície de tools do Think é maior que as tools definidas pelo projeto.** [Configuração](https://developers.cloudflare.com/agents/harnesses/think/configuration/) e [tools](https://developers.cloudflare.com/agents/harnesses/think/tools/) documentam workspace tools, inclusive escrita e `bash`, e MCP automático por padrão. `workspaceBash=false` só remove `bash`. Testar `activeTools`, `beforeToolCall`, colisões de nomes, MCP desativado e o limite real do executor. [MCP remoto](https://developers.cloudflare.com/agents/tools/mcp/) persiste conexões e pode demandar OAuth; cadastro de MCP não é simples exposição de URL e segue fora do primeiro review.
6. **Sandbox anexado ao Agent mudaria o isolamento.** O [guia de Sandbox](https://developers.cloudflare.com/agents/tools/sandbox/) mostra `ctx.container` por instância de Agent e até uma tool genérica `run_command`. Uma instância por shard criaria Sandbox por shard, e a tool de shell ampliaria autoridade. Manter o Sandbox atual por run atrás do executor e somente as três operações de leitura. A VM de Sandbox é isolada do armazenamento e bindings do Agent; isso não substitui a validação de acesso no executor.
7. **Recuperação e cancelamento têm limites próprios.** [Recovery do Think](https://developers.cloudflare.com/agents/harnesses/think/recovery/) é ativo por padrão e limitado por tentativas/trabalho; tools interrompidas são reparadas como erro e não necessariamente reexecutadas. Recuperação de overflow de contexto requer configuração explícita de compaction/classificação. [Fibers duráveis](https://developers.cloudflare.com/agents/runtime/execution/durable-execution/) usam cancelamento cooperativo; uma callback não cooperativa pode terminar depois do cancelamento. Portanto, checar autoridade da run antes de cada tool e antes da publicação, além de cancelar a submissão.
8. **Modelo e transporte precisam de prova integrada.** O novo provider beta [`agents/models/ai-sdk`](https://developers.cloudflare.com/agents/models/ai-sdk/) aceita AI SDK v7/ProviderV4, Workers AI e terceiros via binding `AI`/AI Gateway; inclui Think e streaming. A página não comprova suporte à Dynamic Route `dynamic/pr-review` usada hoje pelo Holon. O [guia de ThinkWorkflow](https://developers.cloudflare.com/agents/harnesses/think/workflows/) lista modelos que funcionam e um exemplo que falha ao emitir a tool forçada em streaming. Testar exatamente a rota e o modelo escolhidos para tool calling e saída final, incluindo composição com o middleware de orçamento; não trocar provider por inferência documental.
9. **Roteamento público não é necessário.** O [guia de routing](https://developers.cloudflare.com/agents/runtime/communication/routing/) mostra `routeAgentRequest` para acesso HTTP/WebSocket. O reviewer em background pode receber apenas chamada interna pela binding/RPC, sem endpoint `/agents/...` público. Testar que `onRequest`, WebSocket e métodos remotos não concedam acesso cruzado a instâncias ou tools.
10. **Tracing é diagnóstico, não ledger.** [Agent tracing](https://developers.cloudflare.com/agents/runtime/operations/observability/tracing/) instrumenta turnos, modelo e tools; armazenamento de mensagens e resultados é configurável e pode expor código privado. [Diagnostics channels](https://developers.cloudflare.com/agents/runtime/operations/observability/diagnostics-channels/) emitem eventos de recuperação e erros; não registrar exceções brutas. O pedido atual é manter `storeMessages` e `storeTools` ligados temporariamente para replay, com alerta de desligamento. Correlacionar com o ledger e verificar a árvore de traces no corte vertical.
11. **Os limites de plataforma não viram orçamento de review.** [Limits](https://developers.cloudflare.com/agents/platform/limits/) descreve limites herdados de Workers/DO, como armazenamento por instância e CPU. Latência de I/O e duração de Workflow são conceitos separados. O teto agregado de inferência e tools do Holon continua sendo política do produto, com reserva antes da chamada de streaming.

## Auditoria do plano e gates antes da implementação

| Prioridade | Estado do plano de migração                                                                           | Correção ou prova necessária                                                                                                                                                                                                                                        |
| ---------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0         | Workflow vigente chama um Agent por shard, mas o mecanismo de espera pelo resultado ainda é abstrato. | Provar um corte vertical que sobreviva a hibernação, retry e supersession. Escolher explicitamente entre submissão durável + leitura de resultado, RPC com contrato terminal seguro, ou mudança de ownership para `ThinkWorkflow`; manter o ledger como autoridade. |
| P0         | Finalização em segundo turno com `Output.object` é proposta, não fato.                                | Testar investigação, `Output.object`, `step.prompt()` como alternativa, e compatibilidade do DeepSeek/rota com tool final forçada em streaming. Escolher a opção que produz objeto validado sem saída parcial nem duplicação indevida.                              |
| P0         | Budget agregado está corretamente desenhado, mas a instrumentação atual cobre só `wrapGenerate`.      | Reservar antes de `wrapStream`, inclusive retries, recovery e compaction; testar concorrência entre shards e liquidação após erro/stream incompleto.                                                                                                                |
| P0         | Tool allowlist está prevista.                                                                         | Testar tools embutidas e MCP ausentes, colisões de nomes, `beforeToolCall`, isolamento da binding do executor e prompt injection. Se usar `step.prompt`, permitir somente o mecanismo interno indispensável à resposta estruturada.                                 |
| P1         | Sessão por run/shard e cancelamento estão previstos.                                                  | Definir identidade estável com digest de configuração, congelamento do prompt, tratamento de `onInterrupted`, estados de submissão, cancelamento cooperativo e checagem de autoridade no executor.                                                                  |
| P1         | Agent tracing está previsto.                                                                          | Validar campos, correlação com Workflow/executor, acesso aos payloads e mecanismo para desligar `storeMessages/storeTools` a pedido. Traces não substituem checkpoints.                                                                                             |
| P1         | Shards maiores e menos numerosos são meta experimental.                                               | Medir limites reais de contexto, bytes de prompt, duração e CPU por turno/instância; não inferir tamanho ótimo do limite máximo de DO.                                                                                                                              |

Não há neste levantamento motivo para introduzir chat UI, Browser Run, Code Mode, `ctx.container`, skills executáveis, MCP privado, follow-up conversacional ou aprovação humana no agente de review. Esses recursos são úteis em outros produtos, mas ampliariam a autoridade ou o escopo sem resolver o problema central do Holon.

## Lacunas que continuam abertas

- Versões concretas compatíveis de `agents`, `@cloudflare/think`, AI SDK e Workers runtime, verificadas no lockfile e no build local.
- Contrato exato de retorno de `submitMessages()`/consulta do resultado ou de RPC pública apropriada ao Workflow atual, confirmado em teste de Durable Object.
- Tool calling em streaming e saída estruturada do modelo/rota escolhidos; as docs não provam a integração DeepSeek + Dynamic Route + Think.
- Compatibilidade de `agents/models/ai-sdk` com Dynamic Routes e com o middleware durável de orçamento; o provider é beta.
- Semântica observada de tracing entre Worker, Workflow, Agent e executor, inclusive payloads e acesso.

Essas lacunas são gates de validação na futura implementação, não autorização para trocar componentes agora.
